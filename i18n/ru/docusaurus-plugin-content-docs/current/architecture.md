# Архитектура

Mjolnir состоит из трёх частей: нативного прокси, который вводит его в процесс игры, закрытого рантайма .NET, который
загружает моды, и SDK — единственного API, который видят моды.

```text
Aska.exe
 └─ UnityPlayer.dll ── импорт ──► version.dll            Mjolnir.Native (C++): прокси системной библиотеки
                                    │ перехватывает il2cpp_init
                                    ▼
                                  CoreCLR (Mjolnir/dotnet)
                                    │
                                    ▼
                                  Mjolnir.Core             закрытый рантайм: interop, Harmony, загрузка модов, изоляция ошибок
                                    │ загружает моды через внутренние контракты
                                    ▼
                                  Mjolnir.SDK + модули     единственный API, который видят моды
                                    │
                                    ▼
                                  Mjolnir/Mods/<mod>/*.dll
```

## Цепочка загрузки {/* #the-boot-chain */}

1. **Загружается прокси.** `UnityPlayer.dll` импортирует `version.dll`, которая не входит в известные DLL Windows,
   поэтому первой загружается копия из папки игры. Она перенаправляет каждый экспорт настоящей `version.dll` в
   системную копию. В любом процессе, кроме `Aska.exe`, она ничего не делает, как и при запуске игры с `--no-mods` или
   при наличии файла `Mjolnir/disable`.
2. **Он ждёт рантайм игры.** Под блокировкой загрузчика Windows прокси только патчит импорты `LoadLibrary*` и
   `GetProcAddress` в `UnityPlayer.dll`. Когда Unity загружает `GameAssembly.dll`, прокси находит
   `il2cpp_init` по имени и ставит на неё обход (detour). Ни один нативный адрес не зашит в код.
3. **Запускается .NET.** После возврата собственной `il2cpp_init` игры обход запускает CoreCLR из приватного .NET 10
   Mjolnir в `Mjolnir/dotnet` и вызывает Core.
4. **Core готовит interop игры** (см. ниже), запускает Il2CppInterop и HarmonyX и загружает моды.
5. **Фаза B** начинается с первого колбэка сцены движка. Core регистрирует собственный компонент в рантайме игры и
   передаёт события кадров игры в SDK и моды.

Любой сбой на этом пути пишется в `Mjolnir/LogOutput.log`, и игра продолжает работать без модов: сбой загрузчика
никогда не должен ронять игру. Исполняемый файл игры никогда не трогается: всё идёт через `UnityPlayer.dll`,
`version.dll` и `GameAssembly.dll`, а игра всегда запускается через Steam.

## Две фазы {/* #two-phases */}

| Фаза | Когда | Разрешено |
|---|---|---|
| A | Внутри `il2cpp_init`, до того как поднят движок | Логирование, конфиг, interop, патчи Harmony, регистрации: `OnLoad` модов |
| B | С первого колбэка сцены движка, примерно через 1,5 с | Объекты Unity, начиная с `OnGameReady`, затем колбэки каждого кадра |

Что это значит для мода: [Жизненный цикл мода](concepts/lifecycle.md#two-phases).

## Interop-сборки {/* #interop-assemblies */}

IL2CPP компилирует игру в нативный код, поэтому .NET-сборок её кода, на которые можно сослаться, нет. Её метаданные
хранят все имена, без шифрования. По ним генератор (Cpp2IL и генератор Il2CppInterop) делает
**interop-сборки**: сборки .NET, типы и методы которых вызывают нативную игру по имени.

Они генерируются на машине игрока и никогда не поставляются:

- Core хранит отметку в `Mjolnir/interop/mjolnir-interop.json`: сборку игры (хеши `GameAssembly.dll` и
  `global-metadata.dat`), версию рантайма Il2CppInterop и версию генератора.
- Когда отметка отличается (при первом запуске, после обновления игры, после обновления Mjolnir), Core запускает
  генератор `Mjolnir/interopgen` отдельным процессом с окном прогресса, раньше, чем загружается что-либо ещё, и ждёт.
  Это занимает около 30 секунд; память расходует генератор, а не игра.
- Результат пишется в новую папку, которая занимает место старой только целиком готовой. Сбой или выбор игроком
  **Запустить без модов** оставляет старую папку, запускает игру без модов и повторяет попытку при следующем запуске.
  Лог генератора — `Mjolnir/cache/interop-gen.log`.

## Загрузка модов {/* #loading-mods */}

- Каждая папка первого уровня в `Mjolnir/Mods` загружается в собственный `AssemblyLoadContext` — для разрешения
  зависимостей. Нативные DLL пропускаются.
- Всё, что есть в `Mjolnir/core` (Core, SDK, Il2CppInterop, HarmonyX…) или `Mjolnir/interop`, всегда разрешается из
  одного общего контекста, поэтому все моды видят одни и те же типы платформы и игры. Копия такой сборки в папке мода
  игнорируется.
- Core находит класс входа каждого мода и читает его манифест из метаданных, поэтому сканирование никогда не выполняет
  посторонние атрибуты мода.
- Граф зависимостей разрешается и сортируется (см. [Зависимости](concepts/lifecycle.md#dependencies)), а моды, которые
  игрок выключил, пропускаются вместе с зависящими от них.
- Каждый мод по порядку создаётся, и вызывается его `OnLoad`. Затем SDK подписывает переопределённые им колбэки на
  события кадров игры.
- Моды никогда не выгружаются: патчи Harmony и типы, внедрённые в рантайм игры, нельзя надёжно откатить.

## Изоляция ошибок {/* #fault-isolation */}

Каждый вызов кода мода идёт через один путь в Core. Исключение там отключает мод, который его выбросил: его колбэки и
обработчики больше не вызываются, а его патчи Harmony остаются. Собственный код Mjolnir никогда не отключается. SDK
вызывает обработчики событий, команды, работы и привязки модов через тот же путь, поэтому мод, выбросивший исключение
внутри события SDK, отключает себя, а не SDK.

## Core и SDK {/* #core-and-the-sdk */}

| Сборка | Роль | Ссылается на |
|---|---|---|
| `Mjolnir.Core` | Запуск, interop, Harmony, сканирование, разрешение зависимостей, изоляция. Закрыта: моды никогда не используют её API | только `Il2Cppmscorlib` и `UnityEngine.CoreModule` движка |
| `Mjolnir.SDK` | Основная библиотека: `Mod`, манифесты, конфиг, локализация, привязываемые значения (bindable), диспетчер, листы персонажей, консоль | Core |
| `Mjolnir.SDK.<Area>` | Один модуль на область игры: UI, Player, Content, AI, World, Stats | основную библиотеку и interop игры |

- Модули обращаются к Core только через основную библиотеку и никогда — друг к другу. То, что нужно каждому модулю
  (потоки, локализация, листы персонажей, реестр консоли), находится в основной библиотеке.
- SDK находит свои модули по атрибуту сборки и запускает каждый один раз, поэтому окно модов существует, даже когда не
  загружен ни один мод.
- Публичные сигнатуры модуля используют только типы .NET, Unity и TextMeshPro. Когда игра что-то переименовывает,
  меняется модуль, а моды продолжают работать.
- Каждая сборка SDK объявляет свой публичный API в `PublicAPI.Shipped.txt` и `PublicAPI.Unshipped.txt`, поэтому каждое
  добавление и каждое ломающее изменение зафиксированы.
- Модули SDK патчат игру собственными скрытыми патчами Harmony и вызывают обычные C#-события. Для всего, что SDK не
  покрывает, у модов остаётся чистый HarmonyX.

## Id контента {/* #content-ids */}

Id того, что добавляют моды (предметов, рецептов, построек, эффектов), — хеши id мода и имени контента и никогда не
выводятся из порядка загрузки. Они одинаковы на каждой машине и при каждом запуске, как того требуют сохранения и
сетевая игра.

## Сетевая игра {/* #multiplayer */}

Сеть игры — Photon Fusion. Mjolnir проверен в одиночной игре и при хостинге мира. Ещё не сделано:

- подключение клиентов к хосту с модами;
- проверка совместимости модов (handshake), которая будет сравнивать моды хоста и клиента по объявлению `Network`
  каждого мода;
- собственные сообщения модов между участниками.
