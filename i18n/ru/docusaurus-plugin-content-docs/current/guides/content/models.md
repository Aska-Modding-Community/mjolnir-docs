# Модели и набор мододела

У предмета мода может быть собственная модель — префаб из AssetBundle, который мод поставляет с собой. Собирайте
бандлы версией Unity игры, **6000.3.12f1**, для Windows, с **HDRP**. Бандл, собранный другой версией Unity, не
загружается.

## Набор мододела {/* #the-mod-kit */}

`unity/Mjolnir.ModKit` в репозитории — проект Unity, настроенный для этого: Unity 6000.3.12f1 с HDRP 17.3.0, конвейером
рендеринга игры.

1. Установите Unity **6000.3.12f1** через Unity Hub и откройте им `unity/Mjolnir.ModKit`. При открытии набор
   включает HDRP на всех уровнях качества (**Mjolnir → Set Up HDRP** делает это ещё раз).
2. Положите ассеты мода в `Assets/Mods/<mod>/<bundle>/`. Каждая такая папка — один бандл со всем её содержимым.
3. Выполните **Mjolnir → Build Bundles**. Команда собирает каждый бандл в `Build/Bundles/<mod>/<bundle>`.
4. Скопируйте файл бандла в папку мода, например в `bundles/models`.

Скрипты в бандлы не попадают: игра не может выполнить `MonoBehaviour` мода из бандла.

При загрузке материалы берут шейдер игры с тем же именем, поэтому используйте шейдеры игры по имени, например
`HDRP/Lit`. Опорная точка модели — начало координат предмета.

## Предмет с моделью {/* #an-item-with-a-model */}

```csharp
ModItem spool = Items.Add("twine_spool", basedOn: "Item_Materials_BasicRope", icon: "items/twine_spool.png")
                     .WithModel("bundles/models", "TwineSpool");
```

`WithModel(bundle, asset)` принимает файл бандла относительно папки мода и имя префаба в нём. В мире предмет ведёт
себя как основа: его так же поднимают, носят, бросают и передают по сети. Меняется только внешний вид:

- префаб заменяет меши основы;
- box-коллайдеры основы подгоняются под модель с тем же зазором, что был вокруг вида основы, так что она лежит на
  земле, дорожке или полке так же, как основа. Собственные коллайдеры префаба не используются;
- подсветка выбора в игре находит рендереры модели.

Модель, которая не загрузилась, пишется в лог, и предмет сохраняет вид своей основы.

```text
Mjolnir/Mods/TwineMod/
├─ TwineMod.dll
├─ items/twine_spool.png
└─ bundles/models
```

## Анимации {/* #animations */}

Клипы и маски для [анимаций](../animations.md#a-mods-own-animations) делаются на собственных скелетах игры:

1. Запустите игру с Mjolnir один раз и загрузите мир с жителями. Mjolnir записывает скелет каждого персонажа (имена
   костей и позу привязки, больше ничего из игры) в `Mjolnir/rigs/<rig>.rig`, когда персонаж появляется.
2. В наборе выполните **Mjolnir → Import Rigs**. Он читает их в `Assets/Mjolnir/Rigs/<rig>.prefab` (`aska` — игрок,
   `peasant_male` и `peasant_female` — жители), каждый с Animator и собственным generic-аватаром, и заново делает
   маски Mjolnir. Папку игры набор берёт из `MJOLNIR_GAME_DIR`, из ранее выбранной папки или из записей Steam, а если
   не находит — спрашивает. Импортированная папка принадлежит игре, поэтому в git не попадает.
3. Анимируйте скелет в окне Animation или назначьте импортированным клипам его аватар. Положите клипы и маски в
   `Assets/Mods/<mod>/<bundle>/` и соберите бандлы так же, как для моделей.

## Пакетная сборка {/* #batch-builds */}

`tools/build-bundles.ps1` в репозитории запускает набор в пакетном режиме и копирует бандлы примеров в
`examples/<mod>/bundles/`. Он находит Unity 6000.3.12f1 в папках установки Unity Hub; `-Unity <path>` или переменная
окружения `MJOLNIR_UNITY` указывают другое место. Unity блокирует открытый проект: сначала закройте редактор или
соберите из его меню и запустите скрипт с `-SkipBuild`.
